# Concurrent Task Scheduling Engine v1.0.0

## 1. Release summary

Version 1.0.0 is the first complete externally reviewable release candidate of
the C17 concurrent task scheduling engine. The final tag and public release
have not been created.

## 2. Main capabilities

The release includes a caller-owned task model, bounded synchronized FIFO,
fixed worker pool, multi-producer submission, deterministic scheduler
lifecycle, accounting, validation, benchmarks, and tests.

## 3. Architecture

Producers submit non-owning task pointers through the scheduler to one bounded
queue. Fixed workers drain the queue and invoke caller callbacks without
holding internal queue or lifecycle locks.

## 4. Reliability

Shutdown closes submission, wakes blocked operations, drains accepted work,
and join releases all native worker resources. Failure paths retain truthful
accounting and safe terminal cleanup.

## 5. Observability

Private versioned snapshots combine lifecycle, worker, atomic callback, and
queue domains. Internal validation reports invariant violations and derives
health without changing runtime behavior.

## 6. Fault injection

Deterministic fault injection covers allocation, worker creation, and join
failures. It is private, compile-time gated, and OFF by default.

## 7. Performance findings

On the documented Intel i5-1155G7 Windows system, tiny callbacks saturated near
two to four workers around the shared queue. CPU workloads scaled through eight
logical workers. See the Phase 7.1 report for exact controls and limitations.

## 8. Robustness audit

GCC 16.1 `-fanalyzer` reported no findings. Strict warnings, ownership,
arithmetic, locking, lifecycle, callback boundaries, and cleanup were manually
audited. ASan, UBSan, and TSan runtimes were unavailable in the tested MinGW
environment, so dynamic-sanitizer coverage is not claimed.

## 9. Build and test matrix

The release candidate validates normal Release/Debug, profiling Release,
fault-enabled Debug, and combined diagnostic Debug. Normal builds register
seven CTests; fault-enabled builds register eight.

## 10. Supported environment

Windows 11 with GCC/MSYS2 UCRT64, MinGW Makefiles, CMake 3.20 or newer, and C17
is the validated environment. Linux and macOS validation is not claimed.

## 11. Installation

Configure and build normally, then run:

```powershell
cmake --install build --prefix build-install
```

Consumers use `find_package(ConcurrentScheduler 1.0 REQUIRED)` and link
`ConcurrentScheduler::concurrent_scheduler`.

## 12. Upgrade notes

The historical runtime version `0.1.0` becomes `1.0.0`. Scheduler, task, queue,
callback, and status-code contracts are otherwise unchanged.

## 13. Breaking changes

There are no API or ABI-structure changes in this release checkpoint. Programs
that asserted the old development version string must update that expectation.

## 14. Known limitations

There is no work stealing, dynamic scaling, real-time guarantee, persistence,
process isolation, callback crash containment, or lock-free queue. Callbacks
remain responsible for their memory safety and synchronization.

## 15. Reproduction

Use the commands in README from a clean source tree. Feature builds explicitly
set profiling or fault injection; both remain OFF by default.

## 16. Release artifacts

Intended artifacts are the tagged source archive and an optional Windows
developer archive containing the installed static library, public headers,
CMake metadata, README, changelog, version file, and MIT License.
